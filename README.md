# NiZ Web

Plum/NiZ/宁芝 mini84v6pro 的网页驱动，使用原厂协议和 WebHID。界面依据 Wootility v5.4.2 的实际演示页面重做：深色双栏导航、顶部配置与保存栏、键盘旁的层选择、下方的按键编辑和功能库。

适配型号：mini84EC(S) V2.3.3，USB 0483:5235，84 键 × 9 层。无需安装桌面驱动，保留原厂固件；不是 QMK 固件或 VIA 协议的移植。

## 使用

网页：[fitzsmith2000.github.io/niz-keyboard-web](https://fitzsmith2000.github.io/niz-keyboard-web/)


使用桌面 Chrome 或 Edge 打开已部署的 HTTPS 页面，点击「连接键盘」，在浏览器授权框选择 mini84v6pro。连接后读取全部配置并自动保存本地备份。

- 点击键帽、选择功能，再点「应用此键」。也可以把功能拖到键帽上。
- 右键点击键帽可撤销该键的修改。
- 组合模式可加入 Command / Win、Option / Alt、Shift 等功能；也可通过「录入快捷键」捕获当前页内的快捷键。系统保留的组合请手动选择。
- 宏和连发使用 NiZ 原厂报告。固定间隔、逐步延时和循环次数可编辑；编辑已有宏保留其原始播放模式。新建宏目前提供指定次数播放。
- 最后点击右上角「保存到键盘」，检查变更，确认后自动备份、完整写入 756 条定义并读回核对。
- 「备份与恢复」支持导入 / 导出 JSON，兼容本项目原生 Mac 应用生成的完整 JSON。连接设备时导入更换按键映射和触发参数；离线导入保留整份备份数据。

离线演示不能向硬件写入。未保存的编辑保存在当前页面，关闭前请导出。本地备份使用 IndexedDB，清除站点数据、更换浏览器或隐私模式可能使其不可见；重要配置请下载留存。

`cc5b51846866aae44493e558ef4e89a820e3490391df35f9c23321b34563f4ce`

## 当前边界

- 仅支持该 mini84v6pro 固件家族的 USB 连接；其他 NiZ 型号、蓝牙和 2.4G 尚未适配。
- 标准 mini84v6pro 支持按键多选、触发上限/下限和共用动态阈值；单位与范围依据原厂界面映射。参数写入与真实触发效果尚未实机验收。
- 当前为非 RGB 设备；灯光区域随备份保留，不开放 RGB 控制。
- 静电容校准已接入官方释放 / 按下采样协议，采用线性流程，支持任意 1～4 键自由采样。固件升级尚未移植。
- 9 层使用原始编号，未将尚未核对的配置组 / Fn 关系标为已确认。
- 写入中断可能留下部分变更。应用不自动宣称恢复成功；请重新读取，从写入前备份恢复到编辑器，再检查并写入。

## 数据与部署

无第三方 JavaScript 运行依赖、统计脚本、远程字体请求或云端配置数据库。Nunito Sans 字体和 Material 图标在本站托管，来源与许可证见 `THIRD_PARTY_NOTICES.md`。键位、宏、按键计数在浏览器和 USB 设备之间处理，不通过网站服务端传输。网站源代码不包含个人键盘配置、按键计数或原生备份文件。

公开网页使用 GitHub Pages 托管，推送到 `main` 后由 `.github/workflows/pages.yml` 检查协议并部署 `dist/`。原 Sites 站点保留账号私有访问。HTTPS 站点和 localhost 都可用 WebHID；file:// 不作为验证入口。

不同网址的浏览器备份互相隔离。迁移到 GitHub Pages 前，可从原网址导出 JSON，再在新网址导入。

## 本地开发

```sh
node --test tests/*.test.mjs
python3 -m http.server 4179 --bind 127.0.0.1 --directory dist
```

在 `http://127.0.0.1:4179/` 打开。可通过环境变量 `NIZ_NATIVE_FIXTURE=/absolute/path/backup.json` 让协议检查额外读取一份本机原生备份，该文件不会加入项目。

主要文件：`dist/protocol.js` 是 NiZ 报告编解码；`dist/hid.js` 是 WebHID 通信；`dist/storage.js` 处理浏览器备份；`dist/app.js` 负责交互。部署清单见 `.openai/hosting.json`。

## 静电容校准

左侧「静电容校准」提供以下流程：

1. 连接并读取 mini84v6pro，保存或撤销已有改键。进入校准模式前自动保存一份键位备份，并暂停普通键盘输入。
2. 松开全部按键，点击「释放采样」。收到官方格式的完成回复后开放按下采样。
3. 自行按住任意 1～4 个需要校准的键，全部按到底，再用鼠标点击「按下采样」。收到完成回复后松开，按需重复，没有固定分组或最低次数。次数仅记录操作，设备不逐键报告实际按压情况。
4. 松开所有按键，结束校准并恢复输入，逐键检查。校准期间可随时退出，不要求按遍全部按键。异常时会尝试恢复输入；页面关闭或 USB 中断后无法输入时，可重连并点击「恢复键盘输入」，或重新插拔 USB。

键位 JSON 不包含电容采样值，无法撤销校准。此轮仅对官方工具做静态协议核对、模拟报告与界面流程测试，未对真实键盘发送释放 / 按下校准指令。真实电容采样和按键效果尚待手工验收。

校准界面检查可在本地服务运行时执行 `python3 tests/browser_calibration.py`，需要 Python Playwright 与本机 Chrome。测试只使用模拟 HID，不连接实体设备。

协议来源与字节记录见 `CALIBRATION.md`。附件仅作为技术资料，未运行其中的应用或执行关闭系统保护等说明。

## 触发行程与 RT

左侧「触发行程与 RT」支持单键、多键、WASD 和全选。调整上限（0.6–3.4 mm）、下限（0.8–3.6 mm）及共用动态阈值（0.1–0.7 mm），应用到页面后由顶部统一检查并保存。只修改 RT 时仅写入触发参数。参数依据、赛事包区别及验证范围见 [RT_PROTOCOL.md](RT_PROTOCOL.md)。

固定触发三档（1.0/2.0/2.8 mm）可用原厂功能「固定触发行程切换」切换；本页的可调上/下限对应动态快速触发区间。

## 实机实时行程

在「触发行程与 RT」中点击「开始全键监测」，直接按任意实体键。界面自动跟随有变化的键，同时显示多个按下键的行程，每键分别保存峰值与近 6 秒曲线。实机连续扫描 84 键平均约 175 ms 一轮，网页显示实际耗时；极短轻点可能漏采。停止、切页或隐藏页面后停止查询。离线演示不生成行程。实机协议通过 IOKit 验证，网页集成通过模拟 WebHID 验证，详见 [TRAVEL_TRACKING.md](TRAVEL_TRACKING.md)。
